## Summary

The technical foundations are excellent:
- no broken links, duplicate titles or orphan pages, and every page is within 2 clicks of the home page;
- mobile Lighthouse scores 100 for performance and SEO;
- structured data validates cleanly;
- AI crawlers are welcome and `llms.txt` is thorough.

The gains now come from the content and the local layer:
- house-rule wording that has drifted on about 50 pages;
- two contraception pages that contradict each other (real data shows they don't compete in search);
- articles that almost never link to the service pages that make money;
- Christmas and holiday hours, which need to be complete in GBP and on the site within the next month;
- a list of "2026" facts to update in the first week of January.

## Live checks (added 26 Oct, after the domain was allowed)

**Findings:**

1. **Medium: Cloudflare hides every email address in the HTML.**
   - **What happens:** the site sits behind Cloudflare (the response headers show `server: cloudflare` and
     `cf-cache-status`). Its "Email Address Obfuscation" feature rewrites each address on every page, for example
     `pharmacy@pricelinepf.com.au` in "Email your eScript to…", into a "[email protected]" link. It then adds a script
     that decodes the address in the visitor's browser.
   - **Who it affects:** people see the address once the script runs. AI assistants and other crawlers that read the raw
     HTML see "[email protected]". That includes the main "send your script ahead" instruction.
   - **Not affected:** the JSON-LD and `llms.txt` still carry the addresses, because Cloudflare doesn't rewrite those.
   - **Fix:** in the Cloudflare dashboard, open the domain, go to Scrape Shield, and switch Email Address Obfuscation
     **Off**. The addresses are already public in the schema and `llms.txt`, so it isn't protecting much.
   - **How you'll know:** view the page source and the plain address appears, with no `/cdn-cgi/l/email-protection`
     links.
2. **Low: Cloudflare doesn't cache the HTML pages** (`cf-cache-status: DYNAMIC`).
   - **What happens:** every page request travels to the VentraIP server in Australia. Measured from Cloudflare's US
     edge, where Googlebot and most AI crawlers fetch from, the first byte took 0.65–1.3 seconds. Images are cached at
     the edge (HIT).
   - **Optional fix:** a Cloudflare cache rule for HTML with a short edge lifetime, for example 10 minutes. Changes would
     then appear up to 10 minutes after each deploy. Speed for local visitors is already good, so this is low priority.

**Passed:**
- **The deploy is current.** Live pages match the latest `main` byte for byte, apart from Cloudflare's email rewriting.
- **Redirects** are single 301s:
  - www to the bare domain;
  - `.com` to `.com.au`;
  - the old WordPress URLs (`/audiology-services/`, `/contact`, `/feed/`, `/tag/…`, `/category/…`, `/?s=`,
    `/sitemap.xml`);
  - missing trailing slashes.
- **Error codes.** `/wp-admin/` returns 410, and unknown URLs return a real 404.
- **Security headers:** HSTS, nosniff, X-Frame-Options, Referrer-Policy and Permissions-Policy.
- **Delivery.** Brotli compression; HTTP/2 and HTTP/3.
- **Crawler access.** Cloudflare doesn't alter `robots.txt` (no managed AI-bot block). Requests with GPTBot, ClaudeBot,
  PerplexityBot, Googlebot and Bingbot user agents all get 200. That's a good sign, but it doesn't prove how Cloudflare
  treats the real, verified bots.
- **Live Lighthouse (mobile).** Home, prescriptions and an article score 100 for performance and SEO, with LCP 1.0–1.4s
  and CLS 0.

## Notes on claude-seo itself

- It installs and runs: 26 skills, 19 agents and 1 hook, adding about 4,700 tokens to every session.
- It is enabled for this repo in `.claude/settings.json`; see `HOW_TO_UPDATE_THE_WEBSITE.md`.
- **Schema hook bug (v2.5.0).** Its schema hook crashes (TypeError) on a JSON-LD `@type` given as a list, which our
  Pharmacy node uses. It only checks `.html` files, so `.astro` edits are unaffected. With a one-line patch, it found 0
  issues on all 141 pages.
- **Reserved name.** `claude plugin validate` flags "claude-seo" as a name reserved for Anthropic. Installs still work
  today, but a future Claude Code release could enforce the rule. Watch for an upstream rename.
